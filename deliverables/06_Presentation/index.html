Executive Summary & Problem Statement

Bridging Linear Television Infrastructure with Digital-First Interactive Streaming
THE BROADCASTING INDUSTRY DILEMMA
  • Linear vs OTT Divide: Conventional linear television lacks real-time audience engagement, while OTT streaming incurs high egress latency and fragmented scheduling tools.
  • Dead-Air Liability: Broadcasters lose revenue and retention when playout programming terminates unexpectedly due to manual scheduling gaps.
  • Cross-Platform Inconsistency: Separate engineering stacks lead to desynchronized playback states, metadata drift, and delayed viewer interactions.
THE OMNICAST SOLUTION ARCHITECTURE
  • Unified Dual-Course Stack: Combines NestJS 10 cross-platform microservices (PRN232) with a reactive Flutter 3.x native mobile client (PRM393).
  • Deterministic 24/7 EPG Playout: Mathematical interval algorithm preventing schedule collisions and eliminating dead-air via automated filler scheduling.
  • Sub-500ms WebRTC Streaming: Real-time broadcast ingest (WHIP) and ultra-low latency playback (WHEP) backed by resilient HLS fallbacks.
  • Dual-Client Synergy: Next.js 15 Broadcaster Studio paired with Flutter mobile consumer app featuring real-time donations and chat.

PRN232: Clean Modular Architecture

Domain-Driven Layered Design with Strict Separation of Concerns
LAYERED PATTERNS & DI
  • Strict Dependency Injection: All services and repositories are injected via NestJS DI containers, enabling complete test mocking.
  • Controllers & DTOs: Incoming HTTP and WebSocket payloads are validated through class-validator and class-transformer.
  • Domain Services: Core business logic isolated from database specifics, maintaining clean application boundaries.
  • Prisma Repositories: Encapsulate data access with strong type generation directly derived from schema models.
ENTERPRISE CROSS-CUTTING CONCERNS
  • Global JWT Auth Guards: Passport-backed token verification with role-based access control (Admin, Staff, Viewer).
  • Custom Exception Filters: Standardized error envelope transforming HTTP exceptions into consistent JSON error models.
  • Logging & Auditing Interceptors: Automatic execution-time tracking and dispatch to the gRPC microservice.
  • 19 Domain Modules: Auth, Users, Media, Channels, EPG, Streaming, Comments, Donations, Analytics, etc.

PRN232: Relational Data Modeling & Supabase

21 Prisma Models, Foreign Key Integrity, and Connection Pooling
DATABASE SCHEMA TOPOLOGY
  • 21 Relational Models: Spans Identity (User, Role, Token), Broadcast (Channel, MediaItem, EpgProgram), and Social (Comment, Donation, AuditLog).
  • Relational Integrity: Strict Foreign Key cascading rules and non-nullable relation constraints preserve database consistency.
  • Optimized Indexing: Composite indexes on (channel_id, start_time) for sub-10ms EPG timeline range scans.
SUPABASE CLOUD INFRASTRUCTURE
  • AWS Seoul Region: Low-latency regional connection to Asian clients and services.
  • Transaction Pooler (pgBouncer): Manages client connection spikes, preventing thread pool exhaustion during peak viewer traffic.
  • Prisma ORM Client: Autogenerated TypeScript types enforce compile-time schema compliance across all 19 modules.

PRN232: 24/7 EPG Linear Scheduling

Collision-Free Playout Planning & Deterministic Dead-Air Elimination
ATOMIC OVERLAP PREVENTION
  • Interval Collision Detection: PostgreSQL interval check: start_time < :new_end AND end_time > :new_start.
  • Transaction Isolation: Concurrent schedule updates execute inside serializable Prisma transactions, preventing duplicate bookings.
  • Timezone Normalization: Playout schedules are normalized to UTC timestamps, preventing daylight savings drifts.
DETERMINISTIC DEAD-AIR FILLING
  • Automated Void Detection: Daemon continuously inspects the timeline for unallocated broadcast gaps.
  • Pseudo-Random Seeding: Computes a deterministic seed from (channel_id + date) to select bumper/filler media matching the exact void duration.
  • Universal Synchronization: All connected viewers on Web and Mobile experience synchronized filler content down to the exact second.

PRN232: AI-Powered Media Curation

Automated Taxonomy, Content Classification, and Resilient Fallbacks
GPT-4o PROMPT ENGINEERING
  • Single-Turn Structured Outputs: Extracts broadcast tags, maturity classifications, and SEO summaries in strict JSON Schema.
  • Automated Ingestion Pipeline: Triggered asynchronously upon media asset upload to avoid blocking the main API thread.
  • Contextual Taxonomy: Tags are matched against broadcast classification standards (News, Entertainment, Sports, Tech).
HEURISTIC RESILIENCY FALLBACK
  • Zero Service Disruption: If OpenAI rate limits or network failures occur, the curator automatically invokes a deterministic keyword extractor.
  • Rule-Based Tagging: Utilizes TF-IDF frequency algorithms to generate tags from asset titles and broadcaster descriptions.
  • Audited State: Every AI curation is timestamped and logged with token usage for billing predictability.

PRN232: Distributed Microservices & gRPC

High-Performance Internal Telemetry & Compliance Auditing
PROTOCOL BUFFERS & HTTP/2
  • Binary RPC Serialization: Strict .proto contracts define AuditLogService and event message structures.
  • HTTP/2 Transport: Multiplexed streams over persistent TCP connections eliminate HTTP handshaking overhead.
  • Strict Typing: Proto files compiled into TypeScript interfaces guarantee contract synchronization across microservices.
AUDIT COMPLIANCE & PERFORMANCE
  • Decoupled Isolation: The Audit-Logger microservice is hosted on Render, isolating compliance logs from user-facing database traffic.
  • Performance Advantage: Binary Protocol Buffers yield a 60% smaller payload and 4x higher throughput compared to JSON REST.
  • Fail-Safe Queuing: Core API utilizes fire-and-forget async RPC calls, ensuring audit logging never introduces latency to broadcast operations.

PRM393: 4-Tier Clean Architecture

Modular Flutter Architecture Isolating Framework, Domain, and Data Layers
PRESENTATION & DOMAIN TIERS
  • Presentation Layer: 31 screens, responsive widgets, custom canvas overlays, listening strictly to BLoC state streams.
  • Domain Layer: Pure Dart use cases and business entities with zero third-party framework or Flutter SDK dependencies.
  • Dependency Inversion: Domain defines repository abstract interfaces; data layer provides concrete implementations.
DATA & CORE INFRASTRUCTURE
  • Data Layer: Repositories coordinate remote REST/WSS datasources with local SQLite storage and SharedPreferences.
  • Core Infrastructure: Service locator (get_it), Dio HTTP interceptors with auto token-refresh, and theme styling.
  • Strict Testability: Decoupled layers enable 100% mocked unit and widget testing without real network access.

PRM393: BLoC State Management Pipeline

Unidirectional Data Flow with Immutable State Transitions
REACTIVE EVENT-DRIVEN PIPELINE
  • Events In, States Out: UI widgets dispatch strongly typed events (e.g., WatchlistToggleEvent, SendChatMessageEvent).
  • Immutable States: States use Equatable to ensure UI only rebuilds when state properties actually change.
  • Transformer Streams: Event debouncing and concurrent handling prevent redundant HTTP requests during rapid taps.
CORE APPLICATION BLOCS
  • AuthBloc: Manages token persistence, login sessions, and auto-logout on refresh token expiration.
  • ChannelBloc: Manages channel catalog discovery, genre filters, and live broadcast state updates.
  • PlayerBloc: Controls OmniPlayer state (playback mode, WebRTC/HLS switching, quality selection, volume).
  • OfflineSyncBloc: Monitors device connectivity and orchestrates offline mutation queue replay.

PRM393: OmniPlayer Dual-Protocol Engine

Ultra-Low Latency WebRTC (WHEP) Playout with Multi-Bitrate HLS Fallback
WEBRTC WHEP PLAYOUT (<500MS)
  • Ultra-Low Latency: Direct WebRTC HTTP Egress Protocol (WHEP) connection to MediaMTX delivers sub-500ms video playback.
  • Real-Time Interactivity: Instant video synchronizes viewer reactions, live donations, and stream chat without delay.
  • Hardware Acceleration: Hardware-decoded H.264/Opus video/audio pipeline reduces mobile battery consumption.
HLS FALLBACK & FLOATING PIP
  • Adaptive Network Fallback: If cellular network bandwidth fluctuates, player smoothly transitions to multi-bitrate HLS.
  • Picture-in-Picture (PiP): Supports system-level floating PiP window on Android, allowing uninterrupted background listening.
  • Custom Gesture Controls: Double-tap to seek, vertical swipe brightness and volume controls, cinema dark UI.

PRM393: Offline-First Architecture & SQLite

Local Persistence, Mutation Queuing, and Background Replay
OFFLINE MUTATION QUEUING
  • Optimistic UI Updates: User actions (save channel, bookmark program) execute immediately in local state.
  • SQLite Persistence: Mutations saved to pending_mutations table with UUID, action type, payload, and retry count.
  • Zero Data Loss: App termination does not destroy pending actions; SQLite safely persists state across device reboots.
AUTOMATED BACKGROUND REPLAY
  • Connectivity Listener: Listens to connectivity_plus network state transitions (cellular/Wi-Fi).
  • Idempotent Sync Worker: Drains pending queue in chronological FIFO order with server-side idempotency keys.
  • Conflict Resolution: Last-Write-Wins strategy backed by server timestamps prevents state overwrite collisions.
