1.1 Problem Statement & Industry Challenges

Contemporary Over-The-Top (OTT) video streaming ecosystems suffer from four fundamental engineering pitfalls:

  • Linear-VOD Fragmentation: Viewers must navigate disjoined interfaces for live linear channels versus on-demand catch-up recordings, causing friction and elevated bounce rates.
  • EPG Collision & Overlap: In broadcast scheduling, overlapping program time-slots corrupt timetable continuity, leading to corrupted streaming ingestion and metadata anomalies.
  • Client Desynchronization: Mobile applications often fail when disconnected from cloud backends, lacking robust offline multi-tier storage for program listings and scheduled alerts.
  • Content Safety Bottlenecks: Human manual review cannot keep pace with high-velocity 24/7 ingestion; platforms require automated, dual-layer AI evaluation before public broadcast.
Core Architectural Value Proposition: OmniCast unifies high-concurrency NestJS modular services, a dedicated gRPC microservice for zero-data-loss audit trails, high-fidelity Three.js 3D cyber portals, and offline-first Flutter mobile clients into a fault-tolerant, unified broadcast topology.

4. Deep-Dive Feature Workflows & Algorithms

4.1 Workflow 1: 24/7 EPG Anti-Conflict Scheduling Algorithm

The anti-conflict engine guarantees timetable integrity by preventing temporal overlaps across the 24/7 schedule. When a Broadcaster schedules a program, the NestJS ProgramsService invokes the anti-collision validation sequence:

1
Temporal Boundary Verification

Broadcaster submits CreateProgramDto with startTime and endTime. System asserts endTime > startTime and validates duration against the source recording.

2
Channel Scope Collision Query

Prisma executes an atomic SQL query: WHERE channelId = :id AND (startTime < :newEnd AND endTime > :newStart) to detect any existing intersect.

3
Conflict Rejection or Atomic Reservation

If overlap count > 0, throws ConflictException (HTTP 409) returning overlapping titles. Otherwise, atomic insertion proceeds and emits an EPG refresh WebSocket broadcast.

4.2 Workflow 2: Dual-Mode AI Curator Inspection Pipeline

Before video broadcasts, the media asset traverses the Dual-Mode AI Curator moderation pipeline:

1
Stage 1: Fast Heuristic Evaluation (< 40ms)

Title, description, and subtitle transcripts are matched against an in-memory lexical bloom filter and regex blacklist for critical safety triggers.

2
Stage 2: Multimodal Deep LLM Inspection

Extracts representative keyframe thumbnails and analyzes contextual safety via OpenAI GPT-4o multimodal vision and TMDB verified metadata.

3
Classification & Telemetry Logging

Calculates confidence scores, assigns statutory rating (P to C), and logs telemetry via the gRPC AuditLogger before releasing the video to public EPG.

4.3 Workflow 3: Mobile Offline-First SQLite Synchronization

The Flutter mobile client delivers an uninterrupted experience even when connectivity drops:

1
Multi-Tier Cache Invalidation & Fetch

Upon connection, Flutter Dio client fetches delta channels and 24h EPG payloads, synchronizing in-memory BLoC state.

2
SQLite Local Database Mutation

Executes batch upsert into omnicast_local.db (tables: channels, epg_programs, watchlist). Offline queries read directly from SQLite.

3
Native Local Notification Scheduling

For each watchlisted program, registers native Android AlarmManager / iOS UNUserNotificationCenter trigger 15 minutes prior to broadcast.

OmniCast leverages PostgreSQL 15+ hosted on Supabase Cloud, managed through Prisma ORM. The data model enforces strict referential integrity, cascading policies, and index optimizations.

Entity / Table Primary Fields & Data Types Relational Constraints & Indexes
User id (UUID), email (VarChar), passwordHash, role (Enum: ADMIN, STAFF, VIEWER), isActive (Bool), vipTier (Enum) Unique index on email. One-to-many with Comment, Watchlist, and AuditLog.
BroadcastChannel id (UUID), name (VarChar), slug (VarChar), category (Enum), streamUrl (Text), isLive (Bool) Unique index on slug. Foreign key target for BroadcastProgram and ProgramRecording.

6.2 Security Shielding & Governance

OmniCast incorporates multi-perimeter defense mechanisms:

  • Cryptographic Password Protection: User passwords hashed with Argon2id and PBKDF2 with dynamic salting, mitigating rainbow table attacks.
  • Token Hardening & RBAC: Short-lived JWT access tokens accompanied by cryptographically secured session storage, verified by NestJS RBAC Guards.
  • Transport Security & Headers: Strict Content Security Policy (CSP), HTTP Strict Transport Security (HSTS), CORS domain isolation, and Helmet headers.
  • gRPC Auditing Sink: All data mutations and administrative elevations are streamed synchronously to an isolated gRPC service ensuring non-repudiation.
